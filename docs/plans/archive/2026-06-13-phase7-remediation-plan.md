## Task 1 — Fix retrieval baseline regression (q030)

**Root cause:** q030 ("What did RFC 7231 originally specify for the HTTP GET method?") expects
`expectedRfcs=[7231]`, but the eval harness calls `SearchAsync` with the default `includeObsolete: false`.
RFC 7231 is obsoleted by 9110, so the reranker applies a `−0.10` penalty that pushes it below
top-10, causing `hit@10=0.889 < 0.90`.

**Fix:** Add a per-question `"includeObsolete": true/false` field to the golden question schema
(default `false`). Update `RetrievalQualityTests` to read this field per question and pass it to
`SearchAsync`. Set `includeObsolete: true` on q030. Update `docs/eval/README.md` to document the
new field.

**Files:**
- `docs/eval/golden_questions.json` — add `"includeObsolete": true` to q030
- `tests/RfcRag.Tests/IntegrationTests/RetrievalQualityTests.cs` — read field, pass to `SearchAsync`
- `src/RfcRag/Evaluation/EvalModels.cs` — add `IncludeObsolete` to the golden question record
- `docs/eval/README.md` — document the new field

## Task 2 — Deduplicate `BuildStatusBlock`

**Root cause:** `SearchService.cs:98` and `ContextAssembler.cs:236` both declare a private static
`BuildStatusBlock(RfcRelationsBatch rel)` with identical bodies.

**Fix:** Add `internal static RfcStatusBlock From(RfcRelationsBatch rel)` to `RfcStatusBlock.cs`.
Remove both private copies and replace all call-sites with `RfcStatusBlock.From(rel)`.

**Files:**
- `src/RfcRag/Search/RfcStatusBlock.cs` — add `From` factory
- `src/RfcRag/Search/SearchService.cs` — remove private method, use `RfcStatusBlock.From`
- `src/RfcRag/Answering/ContextAssembler.cs` — same

## Task 3 — Eliminate redundant `GetRelationsBatchAsync` in `ContextAssembler`

**Root cause:** `SearchService.EnrichWithStatus` already attaches `Status` to every `SearchResult`.
`ContextAssembler.AssembleAsync` builds `EvidenceSection` without copying `result.Status`, then
calls `GetRelationsBatchAsync` a second time in `EnrichAsync` to rebuild the same data.

**Fix:** When creating each `EvidenceSection` from a `SearchResult`, copy `result.Status` into the
section. In `EnrichAsync`, build relation notes and obsoletion warnings from `section.Status`
directly instead of calling `GetRelationsBatchAsync`. Keep the normative-occurrences batch call
unchanged (it's a different table).

**Files:**
- `src/RfcRag/Answering/ContextAssembler.cs` — copy Status on EvidenceSection creation; rewrite `EnrichAsync` to use it

## Task 4 — Fix MCP parameter naming inconsistency

**Root cause:** `RfcAskTools` uses `bool includeObsolete` (camelCase C# name → `includeObsolete`
on the wire), while `RfcRagTools` uses `bool include_obsolete` (snake_case → `include_obsolete`
on the wire). Both expose the same toggle; callers must use different names.

**Fix:** Rename `includeObsolete` → `include_obsolete` in `RfcAskTools.AskRfc`. Update
`FakeAskService` if the name surfaces in test setup, and update `AnswerQualityTests` call-sites.

**Files:**
- `src/RfcRag/Tools/RfcAskTools.cs`
- `tests/RfcRag.Tests/IntegrationTests/AnswerQualityTests.cs` (call-sites)
- `tests/RfcRag.Tests/IntegrationTests/EvalCommandTests.cs` (call-sites)

## Task 6 — Strengthen ranking-order integration test

appear before RFC 7231 in the default ordering.
